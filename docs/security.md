# Security foundation

Runtime secrets belong in ignored `.env` files or environment/secret-manager injection, never source. Frontend VITE variables are public. Example values must be replaced, independently generated, and rotated before use. Root `.gitignore` covers environments, keys, caches, logs and local data. Never print `docker compose config` without `--quiet` when real credentials are loaded.

JWT utilities restrict HS256, require issuer, audience, expiry, issued-at and subject, and reject missing/short signing keys. Production settings require database credentials and a signing key of at least 32 characters. No login, password database, refresh tokens, active-user resolution, RBAC or authentication rate limiting exists yet. `token_subject` is a primitive, not complete user authorization. These belong to Phase 2; never attach it alone to business routes as a complete permission check. No tokens are stored in browser localStorage.

CORS only allows configured exact origins and explicit methods/headers; cookies are not used. No wildcard origins. Structured request logs omit query strings, headers and bodies. Client errors omit database exception text and validation input; request IDs are generated by the server. Health endpoints expose only coarse status, not database addresses or credentials.

Before production: TLS, restricted ingress, a dedicated runtime database role and migration role, dependency locks and vulnerability review, backup encryption, secret rotation, request limits, monitoring, and tested identity policies are required. Docker Compose Phase 1 is a local foundation, not commercial release certification.
